# Backend deployment

Production AAS is a separate Oracle Cloud Ubuntu ARM64 VM. Provision it with `deploy/terraform/oracle-basyx`, then deploy `deploy/oracle-basyx` on that host. The Compose stack runs six BaSyx Go 1.1.0 components, a client-credentials token service, and Caddy; only HTTPS is public and component ports bind to loopback. BaSyx persists to the dedicated Aiven `basyx` database. Run the configuration container once before starting the long-lived services, then configure Render's AAS URLs and token endpoint to the Caddy paths. Keep database/OAuth values only in the VM's untracked `.env`; they are intentionally excluded from Terraform state.

Use the canonical [local and Vercel/Render deployment guide](https://github.com/DruHustle/smart-factory-frontend/blob/main/RENDER_DEPLOYMENT.md). It deploys one supervised, non-root image to a scalable API/web role and a singleton telemetry/notification worker role, with the React frontend on Vercel. Generate the ignored upload files from the existing production environment with `node scripts/split-render-env.mjs .env.prod`, then complete every blank using `.env.prod.api.example` and `.env.prod.worker.example`. Kubernetes is unnecessary; edge equipment stays in the factory.

This repository's quality CI builds/tests .NET on `main`. A push to the dashboard repository's protected `main` branch starts the coordinated production workflow, which resolves backend `main` and edge `master` to full immutable source revisions. It publishes one combined backend image to Render, waits for readiness, then deploys the separate prebuilt React artifact to Vercel. Database changes run in the Render pre-deploy command before any worker starts. Current deployment artifacts do not certify managed-provider credentials, backup/restore, capacity or physical equipment.

For a local split Compose run, copy `.env.local.example`, configure the shared dashboard account DB/token and AAS/MQTT/Redis values, start dashboard Compose/BaSyx first, then `docker compose --env-file .env.local up --build -d --wait`. Do not expose development ports beyond loopback. The Node API delegates to these service names in `BACKEND_DEPLOYMENT_MODE=compose`; host-mode Node uses `local` and ports 5002/5004/5003. TelemetryService defaults to local RabbitMQ; when testing a physical gateway that publishes to CloudAMQP, point only TelemetryService at that broker with `TELEMETRY_MQTT_*` settings, TLS on port 8883, and a separate subscriber identity limited to telemetry/heartbeat reads. Keep the Pi's publish identity and password separate.

.NET 8 support ends 2026-11-11; a supported-runtime migration and complete regression run are required before that date. See [Microsoft lifecycle](https://learn.microsoft.com/en-us/lifecycle/products/microsoft-net-and-net-core).
